# hpe_morpheus_network_server (Resource)

Manages a Morpheus network server: the integration with an external network controller (NSX-T, or the HPE Morpheus SDN controller of an HVM cluster). Most settings are common to all types; type-specific option values are given either in the free-form `config` map or in a typed block.

The network server type is selected with `type_code` (a stable,
environment-independent string, for example `nsx-t` or
`morpheus-junipersdn-network`). Changing it replaces the network server.

Most settings are common to every type. Type-specific option values are given
either in the free-form `config` map — keyed exactly as the type's option types
name them — or, for the HPE Morpheus SDN type, in the typed `config_juniper_sdn`
block. The two are mutually exclusive.

Authentication uses either a username and a write-only password
(`service_username` and `service_password_wo`) or a stored credential
(`credential_id`); the two are mutually exclusive. The HPE Morpheus SDN type
takes no service credentials: its controller is reached from the HVM cluster's
hosts.

The authoritative, environment-specific list of available type codes depends on
which integrations and plugins are installed.

## Example Usage

### NSX-T

```terraform
# NSX-T Network Server
#
# A generic network controller integration. Its type-specific option values go
# in the free-form config map; the common connection fields are attributes. A
# non-SDN network server is attached to the cloud it serves (cloud_id).
resource "hpe_morpheus_network_server" "nsxt" {
  name                = "NSX-T"
  type_code           = "nsx-t"
  cloud_id            = 1
  service_url         = "https://nsxt.example.com"
  service_username    = "admin"
  service_password_wo = "example"
}

# Using a stored credential instead of a username and password:
#
# resource "hpe_morpheus_network_server" "nsxt" {
#   name          = "NSX-T"
#   type_code     = "nsx-t"
#   cloud_id      = 1
#   service_url   = "https://nsxt.example.com"
#   credential_id = 42
# }
```

### HPE Morpheus SDN (Juniper CN2)

```terraform
# HPE Morpheus SDN (Juniper CN2) Network Server
#
# The SDN controller of an HVM cluster is reached from the cluster's hosts, so
# this type takes no service credentials: only the CN2 controller address and,
# optionally, the introspect and sub-tenant toggles. The controller address
# cannot be changed after creation (changing it replaces the network server).
resource "hpe_morpheus_network_server" "juniper_sdn" {
  name      = "HPE Morpheus SDN"
  type_code = "morpheus-junipersdn-network"
  cloud_id  = 1

  config_juniper_sdn = {
    controller_address = "10.0.0.10"
    show_introspect    = false
    enable_sub_tenants = false
  }
}
```

- `network_filter` (String) A filter limiting the networks the server syncs.
- `service_host` (String) The controller host, for types that separate it from the URL.
- `service_mode` (String) The service mode, for types that have one.
- `service_password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The service password for authentication (write-only). Conflicts with `credential_id`.

- `service_token_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) A service token for authentication, for types that take one (write-only). - `service_username` (String) The service username for authentication. Conflicts with `credential_id`.
- `tenant_ids` (Set of Number) The IDs of the tenants allowed to use the network server (private visibility).
- `tenant_match` (String) A tenant match expression, for types that have one.
- `visibility` (String) The visibility of the network server, `private` or `public`.

## Import

Network servers can be imported using the network server ID, e.g.

```shell
terraform import hpe_morpheus_network_server.example 42
```

The write-only values `service_password_wo` and `service_token_wo` are not stored
in state, so the import cannot tell whether the values in your configuration match
the appliance: they are taken as already applied, the plan after import is empty, and a later change to
them is only detected once the resource is next updated for another reason
(Terraform warns about this on every plan until then). To have changes detected
from the start, append the sha256 digest of each configured write-only value to
the import ID, as `<attribute>=<hex>`; several values are separated with `&`:

```shell
terraform import hpe_morpheus_network_server.example "42#service_password_wo=<sha256 hex>"
terraform import hpe_morpheus_network_server.example "42#service_token_wo=<sha256 hex>"
terraform import hpe_morpheus_network_server.example "42#service_password_wo=<sha256 hex>&service_token_wo=<sha256 hex>"
```

The same ID works in an `import` block, where Terraform's `sha256()` function
produces the digest:
`id = "42#service_password_wo=${sha256(var.service_password_wo)}&service_token_wo=${sha256(var.service_token_wo)}"`.
