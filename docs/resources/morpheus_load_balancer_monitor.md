# hpe_morpheus_load_balancer_monitor (Resource)

Manages a Morpheus load balancer health check monitor. Monitors perform periodic health checks against targets to determine their availability. The supported monitor types and configuration fields vary by load balancer type (NSX-T, NSX-V, AVI, etc.).

~> The `config` attribute is a dynamic object whose accepted fields depend on the load balancer type. Only **NSX Advanced Load Balancer (AVI)** supports the `config.monitor.id` (parent monitor) field. NSX-T, NSX-V, HAProxy, and OpenStack load balancer types do not support it. Additionally, HAProxy load balancers have `createMonitors` disabled and do not support monitor management through the API.

## Example Usage

### NSX-T Load Balancer Monitor

The following `monitor_type` values are valid for NSX-T load balancers:

| Value | Description |
|-------|-------------|
| `http` | HTTP active monitor |
| `https` | HTTPS active monitor |
| `icmp` | ICMP ping monitor |
| `passive` | Passive health monitor |
| `tcp` | TCP connection monitor |
| `udp` | UDP datagram monitor |

```terraform
resource "hpe_morpheus_load_balancer_monitor" "nsxt" {
  load_balancer_id    = 1
  name                = "NSX-T HTTP Monitor"
  description         = "An NSX-T HTTP health check monitor"
  monitor_type        = "http"
  monitor_interval    = 5
  monitor_timeout     = 15
  monitor_destination = "/"
  fall_count          = 3
  rise_count          = 3
  alias_port          = 8080
  send_data           = "GET / HTTP/1.1"
  send_type           = "GET"
  send_version        = "HTTP_VERSION_1_1"
  receive_data        = ""
  receive_code        = "200"
  data_length         = 0
  max_retry           = 3
}
```

### NSX-V Load Balancer Monitor

The following `monitor_type` values are valid for NSX-V load balancers:

| Value | Description |
|-------|-------------|
| `dns` | DNS query monitor |
| `http` | HTTP health check |
| `https` | HTTPS health check |
| `ldap` | LDAP bind monitor |
| `mssql` | Microsoft SQL Server monitor |
| `tcp` | TCP connection monitor |
| `udp` | UDP datagram monitor |

```terraform
resource "hpe_morpheus_load_balancer_monitor" "nsxv" {
  load_balancer_id            = 1
  name                        = "NSX-V HTTP Monitor"
  description                 = "An NSX-V HTTP health check monitor"
  monitor_type                = "http"
  monitor_interval            = 10
  monitor_timeout             = 15
  max_retry                   = 3
  send_data                   = "GET / HTTP/1.0"
  send_type                   = "GET"
  receive_data                = ""
  receive_code                = "200"
  monitor_destination         = "/health"
  monitor_username            = ""
  monitor_password_wo         = ""
  monitor_password_wo_version = 1
}
```

## Schema

### Required

- `load_balancer_id` (Number) The ID of the load balancer associated with the monitor
- `name` (String) The name of the load balancer monitor

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `alias_port` (Number) An alternative port to use for health checks if different from the target port
- `config` (Attributes) Configuration object with parameters that vary by monitor type (see [below for nested schema](#nestedatt--config))
- `data_length` (Number) The length in bytes of the data payload for ICMP echo requests
- `description` (String) A description of the load balancer monitor
- `extra_config` (String) Additional monitor extension configuration. Used with NSX-V load balancer monitors to provide extension parameters for specific monitor types (e.g. http, https, tcp, udp, dns, mssql, ldap). This field is write-only and not returned by the API.
- `fall_count` (Number) The number of consecutive failed health checks before marking the target as down
- `max_retry` (Number) The number of retries before the health check is considered failed
- `monitor_destination` (String) The target path or URL for the health check (e.g. /health)
- `monitor_interval` (Number) The interval in seconds at which the monitor checks target health
- `monitor_password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The password for authenticated health checks (Write Only)
- `monitor_password_wo_version` (Number) Monitor password version. Used to determine if monitor_password_wo has been updated.
- `monitor_timeout` (Number) The maximum time in seconds to wait for a health check response before marking as failed
- `monitor_type` (String) The monitor protocol type. Valid values are: dns, http, https, icmp, ldap, mssql, passive, tcp, udp. The provider maps these to the appropriate load-balancer-specific value based on the load balancer type (e.g. http becomes LBHttpMonitorProfile for NSX-T).
- `monitor_username` (String) The username for authenticated health checks
- `receive_code` (String) A comma-separated list of HTTP status codes expected for a successful health check (e.g. "200" or "200,201")
- `receive_data` (String) The expected response body string to validate in the health check response
- `rise_count` (Number) The number of consecutive successful health checks before marking the target as up
- `send_data` (String) The request body to send to the target during health checks
- `send_type` (String) The HTTP method for the health check request (e.g. GET, POST, HEAD)
- `send_version` (String) The HTTP protocol version to use in health check requests (e.g. HTTP/1.0, HTTP/1.1)
