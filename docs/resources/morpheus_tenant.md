# hpe_morpheus_tenant (Resource)

Manages a Morpheus tenant (account). A tenant is an isolated administrative
boundary with its own users, roles, groups and resources.

Creating a tenant has significant side effects: Morpheus generates a Cypher
master key for the tenant, creates its initial groups, and clones every
multitenant user role into the new tenant. Changing base_role_id propagates
the base role across the tenant's derived roles, and changing currency
restarts account usage calculation asynchronously.

## Example Usage

```terraform
# Look up the base role by name using the role data source.
data "hpe_morpheus_role" "example" {
  name = "Tenant Admin"
}

resource "hpe_morpheus_tenant" "example" {
  name            = "Example Tenant"
  description     = "Terraform example tenant"
  enabled         = true
  subdomain       = "tfexample"
  base_role_id    = data.hpe_morpheus_role.example.id
  currency        = "USD"
  account_number  = "12345"
  account_name    = "tenant 12345"
  customer_number = "12345"
}
```

### Creating a subtenant under a specific parent

By default a tenant is created under the caller's own tenant. To create a
subtenant under a specific parent tenant — which is only permitted when
authenticated as the master tenant — set `parent_id`. The example below
resolves the parent's ID by name with the `hpe_morpheus_tenant` data source.
Changing `parent_id` forces a new resource.

```terraform
# Look up the base role by name using the role data source. The base role must
# be one the parent tenant can assign; a tenant's own base role always is.
data "hpe_morpheus_role" "example" {
  name = "Tenant Admin"
}

# Look up the parent tenant by name using the tenant data source.
data "hpe_morpheus_tenant" "parent" {
  name = "Parent Tenant"
}

# Create a subtenant under that parent. Nominating a parent is only permitted
# for the master tenant, and changing parent_id forces a new resource.
resource "hpe_morpheus_tenant" "subtenant" {
  name         = "Example Subtenant"
  description  = "Terraform example subtenant"
  base_role_id = data.hpe_morpheus_role.example.id
  parent_id    = data.hpe_morpheus_tenant.parent.id
  subdomain    = "subtenant"
  currency     = "USD"
}
```

~> **Note** `parent_id` requires **Morpheus 8.1.0 or later**, which introduced
the tenant hierarchy. Earlier appliances silently ignore a nominated parent, so
the provider refuses a configuration that sets `parent_id` at plan time on
those versions; omit it, and the tenant is created under the caller's own
tenant as before. On appliances older than 8.1.0 the read-only `parent_id`,
`parent_name` and `parent_subdomain` attributes are always `null`. Everything
else the resource does is supported on all Morpheus versions the provider
supports.

## Schema

### Required

- `name` (String) The name of the tenant.

### Optional

- `account_name` (String) An optional field that can be used for billing and accounting.
- `account_number` (String) An optional field that can be used for billing and accounting.
- `base_role_id` (Number) The ID of the tenant's base role, which restricts the access available to this tenant's roles and users. The role must be one of the parent tenant's available account roles (the parent is parent_id, or the authenticated user's tenant when that is omitted); supplying an ID that is not available to the parent fails with an "Invalid role id" error. When omitted, Morpheus assigns the master tenant's default account role if the parent is the master tenant -- so base_role_id can be computed to a role you did not set -- and otherwise fails with a "Role is required" error. (Morpheus versions before 8.1.0 have no tenant hierarchy and always assign the default account role when base_role_id is omitted.)
- `currency` (String) Currency ISO 4217 code for the tenant (e.g. USD, EUR, GBP). Must be a currency enabled on the target appliance; validated at plan time against the live currency list.
- `customer_number` (String) An optional field that can be used for billing and accounting.
- `description` (String) The description of the tenant.
- `enabled` (Boolean) Whether the tenant is enabled. Disabled tenants cannot be logged into.
- `parent_id` (Number) The ID of the parent tenant. When set on create, the new tenant is created under this parent; this is only permitted when authenticated as the master tenant, and base_role_id must be a base role valid for the nominated parent. When omitted, it defaults to (and is computed as) the tenant of the authenticated user. Bound on create only, so changing it forces a new resource. Requires Morpheus 8.1.0 or later: earlier appliances have no tenant hierarchy, so setting parent_id is refused at plan time and, when omitted, it is computed as null.
- `remove_resources` (Boolean) Delete-time only. When true, destroying this resource also
de-provisions the tenant's managed instances (removing the underlying
VMs). When false (the default), the tenant is removed from Morpheus but
its provisioned resources are left running. Has no effect on create or
update.
- `subdomain` (String) The custom login subdomain (login URL prefix) for sub-tenant users. May contain only letters, numbers, and hyphens, must not start or end with a hyphen, must be 1-63 characters long, cannot be entirely numeric, and must be globally unique across all tenants.

### Read-Only

- `base_role_name` (String) The authority (name) of the tenant's base role.
- `date_created` (String) The date the tenant was created.
- `external_id` (String) The external ID of the tenant.
- `id` (Number) The ID of the tenant.
- `instance_count` (Number) The number of instances in the tenant.
- `last_updated` (String) The date the tenant was last updated.
- `master` (Boolean) Whether this is the master tenant.
- `parent_name` (String) The name of the parent tenant. Null on Morpheus versions before 8.1.0, which have no tenant hierarchy.
- `parent_subdomain` (String) The subdomain of the parent tenant. Null on Morpheus versions before 8.1.0, which have no tenant hierarchy.
- `user_count` (Number) The number of users in the tenant.

## Import

Import is supported using the numeric tenant ID.

~> **Note** `remove_resources` is a delete-time-only flag that the Morpheus API
does not return, so it is `null` immediately after an import. Re-apply your
configuration to reconcile it.

-> **Note** The master tenant can be imported and, when authenticated as the
master tenant, updated — but Morpheus does not allow it to be disabled, has no
base role for it, and rejects deleting it. Setting `enabled = false` or
`base_role_id` on it, or destroying it, returns a diagnostic naming the
restriction; use `terraform state rm` to stop managing an imported master
tenant.

```bash
terraform import hpe_morpheus_tenant.example 123
```
