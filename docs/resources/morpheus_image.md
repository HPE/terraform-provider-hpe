# hpe_morpheus_image (Resource)



Image resource allows creation of Morpheus images to be used for instance
provisioning.

-> `user_data` must not contain leading and trailing whitespace. Use built-in
Terraform function 
[`trimspace`](https://developer.hashicorp.com/terraform/language/functions/trimspace)
to remove all leading and trailing whitespace.

-> Images will be replaced if there are any changes to the following atributes:<br>
&nbsp;&nbsp;&nbsp;&nbsp;- `url`<br>
&nbsp;&nbsp;&nbsp;&nbsp;- `config_azure`<br>
&nbsp;&nbsp;&nbsp;&nbsp;- `description`<br>
&nbsp;&nbsp;&nbsp;&nbsp;- `image_type`<br>
&nbsp;&nbsp;&nbsp;&nbsp;- `storage_provider_id`

-> Removing `labels`, `min_disk`, `os_type_id`, `ssh_username`, `user_data` or `tenant_ids` from the
configuration clears it on the image. `min_ram` keeps its value when it is removed, because Morpheus
rejects an empty minimum memory; `description` and `storage_provider_id` are set when the image is
created and keep their value too.

## Example Usage

```terraform
resource "hpe_morpheus_image" "example_image" {
    name = "Alpine Example Image"
    description = "this is an example image"
    labels = ["terraform-image"]
    image_type = "qcow2"
    url = "https://dl-cdn.alpinelinux.org/alpine/v3.22/releases/cloud/generic_alpine-3.22.2-x86_64-bios-cloudinit-r0.qcow2"
    storage_provider_id = 196
    auto_join_domain = true
    cloud_init = true
    os_type_id = 75
    ssh_username = "alpine"
    min_ram = 1
    min_disk = 20
    trial_version = true
    user_data = trimspace(
    <<-EOT
    #!/bin/sh
    apk add --no-cache bash
    EOT
    )
    virtio_supported = true
    visibility = "public"
}
```

## Import

Import is supported using the resource ID.

```bash
terraform import hpe_morpheus_image.example 123
```

The write-only value `ssh_password_wo` is not stored in state, so the import
cannot tell whether the value in your configuration matches the appliance: it is taken as already
applied, the plan after import is empty, and a later change to it is only detected once the
resource is next updated for another reason (Terraform warns about this on every plan until then).
To have changes detected from the start, append the sha256 digest of each configured write-only
value to the import ID:

```shell
terraform import hpe_morpheus_image.example "123#ssh_password_wo=<sha256 hex>"
```

The same ID works in an `import` block, where Terraform's `sha256()` function produces the digest:
`id = "123#ssh_password_wo=${sha256(var.ssh_password_wo)}"`.
