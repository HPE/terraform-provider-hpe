# hpe_morpheus_network_floating_ip (Resource)

Allocates a Morpheus network floating IP from a floating IP pool on an SDN network server, and tracks its details. Floating IPs are released when the resource is destroyed. The floating IP pool and the network server it is allocated from are not returned by the API, so they are kept in Terraform state.

The floating IP is allocated from a floating IP pool on an SDN network server.
Neither the pool nor the network server is returned by the API, so both are kept
in Terraform state; changing either replaces the resource.

Floating IP pools are defined on the SDN router of a cluster resource pool
(`hpe_morpheus_network_router` with `config_juniper_sdn.floating_ip_pool_ids`)
and are discoverable through the `hpe_morpheus_option_source_values` data source
with the option source `juniperFloatingIpPools`, passing the resource pool as
`parameters = { juniperResourcePool = "<id>" }`.

Destroying the resource releases the floating IP. A floating IP that is still
attached to a VM cannot be released; detach it first.

~> **Release may be reported as successful when it was not.** SDN plugin 1.1.0
reports a successful release when the floating IP record has no controller
reference or has already gone, even though the floating IP on the controller was
not deleted. Morpheus then removes its own record and Terraform drops the
resource from state, leaving an orphaned floating IP on the controller. The
orphan can collide with later allocations from the same pool, which then fail
until the pool is recreated on the controller. After destroying a floating IP on
an affected plugin, check the controller for the leftover object.

## Example Usage

```terraform
# Allocate a floating IP from a pool on an SDN network server.
#
# The floating IP pool and the network server are not returned by the API, so
# they are kept in Terraform state; changing either replaces the resource.
# Floating IP pools are defined on the SDN router of a cluster resource pool
# and are discoverable through the option source, filtered by that pool; the
# option source returns ids as strings.
data "hpe_morpheus_network_server" "sdn" {
  name = "HPE Morpheus SDN"
}

data "hpe_morpheus_option_source_values" "floating_ip_pools" {
  source     = "juniperFloatingIpPools"
  parameters = { juniperResourcePool = "1" }
}

resource "hpe_morpheus_network_floating_ip" "example" {
  network_server_id   = data.hpe_morpheus_network_server.sdn.id
  floating_ip_pool_id = tonumber(data.hpe_morpheus_option_source_values.floating_ip_pools.values[0].value)
}
```

Pools are discoverable through the hpe_morpheus_option_source_values data source with option source `juniperFloatingIpPools`. Not returned by the API, so it is kept in Terraform state. - `network_server_id` (Number) The ID of the network server (SDN controller) to allocate the floating IP from. Not returned by the API, so it is kept in Terraform state. Changing it replaces the resource.

## Import

A floating IP can be imported using its ID. Because the network server and
floating IP pool it was allocated from are not returned by the API, importing
with the ID alone leaves both null in state, and the next plan shows a
replacement:

```shell
terraform import hpe_morpheus_network_floating_ip.example 42
```

To import cleanly, append the network server ID and floating IP pool ID in the
form `<id>:<network_server_id>:<floating_ip_pool_id>`:

```shell
terraform import hpe_morpheus_network_floating_ip.example "42:7:9"
```
