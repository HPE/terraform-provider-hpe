# hpe_morpheus_appliance_setup (Resource)

Performs the first-time setup of a freshly installed Morpheus appliance: waits for its API to come up, then creates the master tenant and its first administrator through the unauthenticated setup endpoint the setup wizard uses, optionally installing a licence key. An appliance already set up is adopted as is (`already_initialised = true`). Setup happens once: later changes to identity inputs are refused, and destroying the resource changes nothing on the appliance.

The setup wizard a browser shows on a new appliance is a front end for two unauthenticated endpoints, `GET /api/setup/check` and `POST /api/setup/init`, and this resource drives them with the provider's `url` and `insecure` settings but none of its credentials. The provider's `username` and `password` are normally the administrator this resource creates: the provider only authenticates when another resource or data source first calls the API, so the resource can run before those credentials exist, and everything else should `depends_on` it.

## Example Usage

```terraform
# The password and licence key never reach the plan or the state: they are
# write-only attributes. Read them from a secret store or an ephemeral resource.
variable "admin_password" {
  type      = string
  sensitive = true
  ephemeral = true
}

variable "license_key" {
  type      = string
  sensitive = true
  ephemeral = true
  default   = null
}

# The provider's url points at the new appliance; its credentials are the
# administrator this resource creates, so every other resource depends on it.
resource "hpe_morpheus_appliance_setup" "example" {
  appliance_name = "morpheus.example.com"
  account_name   = "My Company"
  username       = "admin"
  password_wo    = var.admin_password
  email          = "admin@example.com"
  first_name     = "Morpheus"
  last_name      = "Admin"
  license_key_wo = var.license_key

  timeouts = {
    create = "40m"
  }
}
```

## Behaviour

- **Create** polls `/api/setup/check` until the appliance's API answers, within the create timeout (default 40 minutes: a first boot seeds the database before the API comes up). When the appliance reports that setup is needed, one `POST /api/setup/init` creates the master tenant, the administrator and the appliance record and, when `license_key_wo` is set, installs the licence; the appliance validates the key before it creates anything, so a bad key fails the apply and leaves the appliance untouched. When the appliance has already been set up, nothing is sent, `already_initialised` is `true` and a warning says so.
- **Refresh** asks the appliance whether setup is needed. Refresh and import each have a one-minute operation deadline (or the caller's shorter deadline), including the build-version lookup. An appliance that says so again has been reinstalled behind the same URL: the resource is removed from state and the next apply sets it up again. An appliance whose API does not answer is an error, not a removal, so setup is never re-run blind. `build_version` is read with the provider's credentials and kept as it was when they do not work.
- **Changing** recorded identity inputs (including the appliance URL/name, tenant, administrator, email and Hub mode) is refused at plan and apply time; setup happens once. Removing a recorded optional identity value is also refused, rather than silently discarding the guard against later changes. Unrecorded (null) fields may adopt configuration metadata, including after import; already recorded fields remain protected independently. Manage the tenant, user, appliance settings and licence afterwards through their dedicated resources or the appliance UI (`hpe_morpheus_license` for the key). Write-only password and licence inputs are bootstrap-only: changing them does not rotate credentials or reinstall a licence, including during adoption or replacement. Changing the provider's username/password to match new bootstrap inputs can therefore break authentication against the unchanged appliance; update the real credentials through the appropriate API/UI first.
- **Destroy** forgets the resource and leaves the appliance set up.

## Schema

### Required

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `account_name` (String) Name of the master tenant to create.
- `email` (String) Email address of the first administrator.
- `password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Password of the first administrator; it must satisfy the appliance's password policy. Write-only: sent once at setup and never stored in state or plan. Changing it later has no effect on the appliance.
- `username` (String) Login of the master tenant's first administrator.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `appliance_name` (String) A name for the appliance instance. When omitted the appliance generates a random identifier.
- `appliance_url` (String) The URL the appliance records as its own (*Administration > Settings > Appliance URL*); hosts and agents call back to it. Defaults to the provider's `url`.
- `first_name` (String) First name of the first administrator.
- `hub_mode` (String) How setup deals with Morpheus Hub: `skip` (the default) registers nothing; `login` and `register` use the hub credentials already entered on the appliance. A licence key implies `skip`.
- `last_name` (String) Last name of the first administrator.
- `license_key_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) Licence key to install during setup. The appliance validates it before creating anything, so a bad key fails the setup and leaves the appliance untouched. Without a key the appliance installs its default trial licence. Write-only; to manage the licence afterwards use `hpe_morpheus_license`.
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))

### Read-Only

- `already_initialised` (Boolean) Whether the appliance had already been set up when the resource was created, in which case nothing was sent and the configured tenant and user may not be the ones on the appliance.
- `build_version` (String) The appliance's build version, as reported after setup and on each refresh that can authenticate with the provider's credentials; null until then.
- `id` (String) Resource identifier: the appliance URL the provider is configured with.

## Import

Import is supported using the appliance URL the provider is configured with; the appliance must already be set up. The required inputs are not known to the appliance and are taken from the configuration on the next apply, which changes nothing on the appliance.

```shell
terraform import hpe_morpheus_appliance_setup.example https://morpheus.example.com
```
